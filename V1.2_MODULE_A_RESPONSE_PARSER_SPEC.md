# AI-OS V1.2 Module A
# Response Parser Specification


## Module

External Model Response Parser


## Status

ARCHITECTURE REVIEW


## Goal

Normalize different external model responses
into AI-OS standard response format.


## Architecture


External Model

↓

ConnectionClient

↓

Response Parser

↓

RealProvider

↓

Model Router

↓

LLM Gateway



## Responsibilities


Response Parser:


Allowed:

- Parse model response
- Extract text
- Extract model information
- Normalize status
- Handle invalid response


Not responsible:

- Task planning
- Device control
- Security decisions
- Memory operations



## Standard Response


Success:


{
"text":"",
"model":"",
"confidence":0,
"status":"success"
}



Failure:


{
"text":"",
"model":"",
"confidence":0,
"status":"unavailable"
}



## Parsing Rules


Valid response:


Extract:

- generated text
- model name
- confidence if available


Missing fields:


Use defaults.


Example:


missing confidence

↓

confidence = 0



## Error Handling


Invalid response:


↓

status = unavailable


Cases:


- empty response
- invalid format
- missing required data
- parser error



## Security Boundary


Parser cannot:


- Execute commands
- Access devices
- Modify AI-OS state



## Provider Integration


RealProvider uses parser.


Chain:


ConnectionClient

↓

Response Parser

↓

RealProvider

↓

Standard Response

Tests:

- Empty response
